# v0.1.2 — queued prompts are not failures

A send while the agent was busy was admitted into the queue and then reported
as `发送失败`: the gateway waited 3.6 s for a `user/message` event, but a queued
prompt does not become a transcript event until the running turn ends. The page
kept the text, the user retried, and each retry queued another copy — a real
session ended up with three identical prompts waiting.

## What changed

- **The gateway trusts prompt admission.** `sessionController.prompt()` resumes
  a cold session, validates the content and resolves only after the Agent has
  taken the message into its inbox. That is a success, whether the message
  starts a turn now or waits in `inbox.nextTurn` for the current one to finish.
  The surface poll that produced the false error is gone.
- **Retries are idempotent.** The page sends a stable `requestId` per attempt;
  the gateway forwards it as the prompt's `rpcId`, so the controller can
  recognise a retry (`hasPromptRequest`) instead of queueing a second copy. A
  timeout response says so explicitly instead of looking like a lost message.
- **A queued send is acknowledged.** If the turn is running, the composer shows
  `已排队 · 当前回合结束后发送` rather than leaving the phone looking stuck
  until the bubble appears.
- **An error no longer erases the conversation.** A failed send appends one
  line under the messages; the old code replaced the whole transcript. The
  gateway's JSON `{error}` is parsed, so the phone no longer shows raw JSON.
- **The 工作区 back button no longer loses to a late refresh.** Opening a
  session or returning to the list starts an async read; a session response
  that landed after the back tap used to repaint the conversation over the
  list. Every navigation now bumps a view sequence, and a response from an
  older view is discarded. The list is also painted immediately on back.
- **Phone-created Sessions join their Workspace.** The `＋` used to call
  `sessionController.create({cwd})`, which sets the directory but does not
  attach the Session to a Workspace — on the desktop those Sessions appeared
  under “Ungrouped” while the phone's list hid it by grouping loose Sessions by
  cwd. `create()` now resolves the directory to its Workspace and passes
  `workspaceId`. `scripts/attach-sessions.mjs` repairs Sessions created by the
  old build (run it while the app is quit; it backs up `workspace.json`).
- **Approval ownership follows the message, not the send.** `phoneTurns` is set
  when the phone's `user/message` (matched by `rpcId`) is committed, and cleared
  on every `turn/end` even when no phone stream is open. A prompt queued behind
  a desktop turn cannot make that turn phone-owned.

## Upgrade

```bash
dsh plugin --profile desktop add dsh-mobi-web@0.1.2
# restart the app
```

`lib/page.html` is read per request, so the UI half appears on a refresh; the
gateway change (`lib/index.js`) needs the restart. The token and cookie do not
change.
