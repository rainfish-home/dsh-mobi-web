# v0.1.1 — desktop approval status

A small release about the one case where the phone used to look broken: the
desktop was waiting on an approval, the phone showed a running turn, and
nothing said why.

## What changed

- **A read-only “PC is waiting for approval” banner on the phone.** When the
  gateway delegates an approval to the desktop — or when a desktop-origin
  approval arrives while the phone is not watching — the session view now
  shows the tool name and a plain-language hint that the desktop has to
  continue. It updates over SSE and is re-sent with the session payload, so
  it survives a reconnect, a page refresh and a lock screen.
- **Session-list marker.** A session with a pending desktop approval carries a
  `等待电脑审批` / waiting marker on its row, so the list no longer shows a
  running session with no explanation.
- **The stale phone card is dismissed.** The desktop-origin grace window can
  hand a request back after the phone has already rendered a card; that card
  used to stay tappable and fail with “already handled”. It is now replaced by
  the read-only banner.
- **No takeover.** The phone still does not answer desktop-owned approvals.
  This release only observes them, which keeps the existing origin-affinity
  decision intact.

## Implementation notes

- The gateway listens to the durable `approval/asked` / `approval/decided`
  session events and keeps a per-session pending map. The read path also
  derives the same state from the session surface, so a gateway restart or a
  reconnect does not lose the status.
- No new dependencies, routes, config keys or permissions. The mobile API adds
  two response fields: `desktopApprovals` on `GET /m/api/session` and
  `waiting` on each `GET /m/api/sessions` item.
- 34 tests, including seven for the pure surface scanner.

## Upgrade

```bash
dsh plugin --profile desktop add dsh-mobi-web@0.1.1
# restart the app
```

The session cookie and token do not change; the phone does not need to log in
again.
